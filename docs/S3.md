# S3 mirror

The collected datasets (`records/`, `courts/`, `liens/`, `coverage.json`, and
the legacy Reddit corpus in `data/`) are mirrored to one S3 bucket. Local
files are the working copy; S3 is the durable copy and the way a fresh
checkout gets the data back without re-collecting it. Pushes are explicit —
collectors run with `--no-upload` and the mirror is refreshed afterwards with
`scripts/s3_push_all.sh`. Member data (`reviews.db`), cookies and `.env`
never go up; the CLI refuses them.

## Where the code lives

| File | Role |
| --- | --- |
| `hoaspy/lib/s3_sync.py` | The mirror library + CLI: bucket/prefix resolution, credential fallback, `push` / `pull`, conflict detection, the access check |
| `scripts/s3_push_all.sh` | Pushes every dataset file under its prefix (run from anywhere; it `cd`s to the repo root) |
| `config.yml` (`s3:` block) | Bucket name, default prefix (`reddit-video/`, the legacy corpus), region, server-side encryption |
| `.env` (git-ignored) | Fallback credentials `ACCESSKEYID` / `SECRETACCESSKEY` (optional `REGION`) |
| `<dir>/.s3_sync.json` (git-ignored) | Per-directory marker: the remote ETag last seen for each file |
| `hoaspy/collect/registries/get_records.py`, `hoaspy/collect/liens/get_liens.py`, `hoaspy/collect/liens/get_miamidade_liens.py` | The only collectors that still push on their own when run without `--no-upload` |
| `hoaspy/reddit/scrape_hoa.py` | Legacy collector with its own `--push` / `--pull` (see REDDIT.md) |

## The bucket

- **Name:** `prixe--use1-az4--x-s3`, from `config.yml` `s3.bucket` (the
  `S3_BUCKET` env var overrides it — `resolve_target()`).
- **Type:** an S3 Express One Zone *directory bucket*. `is_directory_bucket()`
  recognises the `--x-s3` suffix, and `get_client()` derives the region from
  the name (`use1` → `us-east-1`) because directory buckets must be addressed
  from their own region. Two consequences `check_access()` warns about on
  every run: single-AZ storage and no versioning — fine as a working copy,
  not an archive of record — and no public-access block to check (directory
  buckets are private by construction).
- **Encryption:** every upload sets `ServerSideEncryption` from `s3.sse`
  (`AES256` by default; `null` disables it). Content types are set from the
  extension (`.jsonl` → `application/x-ndjson`, `.json`, `.csv`).
- **Permissions needed:** `s3:GetObject`, `s3:PutObject`, `s3:ListBucket` on
  the bucket — nothing wider.

## Run / operate

Push everything after collectors finish:

```bash
./scripts/s3_push_all.sh
```

Push or pull a specific list of files (names are relative to `--dir`;
`--prefix` is required and gets a trailing slash added if missing):

```bash
./venv/bin/python -m hoaspy.lib.s3_sync push --prefix hoa-records/ --dir records state_registries.jsonl
./venv/bin/python -m hoaspy.lib.s3_sync pull --prefix hoa-courts/ --dir courts dockets.jsonl opinions.jsonl
./venv/bin/python -m hoaspy.lib.s3_sync push --prefix hoa-liens/ --dir liens --force liens.jsonl   # overwrite a conflict
```

Flags (`main()` in `hoaspy/lib/s3_sync.py`): `push|pull`, `files...`,
`--dir` (default `.`), `--prefix`, `--config` (default `config.yml` at the
repo root), `--force`, `-v`. Exit codes: `2` for a refused file or no bucket
configured, `1` for an S3 error (unreachable bucket, access denied, missing
credentials, or a push conflict), `0` otherwise.

Collectors that push on their own when run **without** `--no-upload`
(`get_records`, `get_liens`, `get_miamidade_liens`): they push their own
`SYNCED` list (`associations.*` + `sources.json`; `liens.*`,
`by_association.csv` + `sources.json`; `liens_miamidade.*` + `sources.json`)
to `--prefix` (`hoa-records/` / `hoa-liens/`). Every other collector accepts
`--no-upload` for parity and never uploads (`get_tx_research` only logs a
reminder). The project convention is to run all of them with `--no-upload`
and push in one place with the script.

## How push and pull behave

- **Pull** downloads only files missing locally (all of them with `--force`)
  and records each object's ETag in `.s3_sync.json` beside the files. A key
  absent in S3 is skipped silently — normal on a first run.
- **Push** uploads each listed file that exists locally. Before uploading it
  compares the remote ETag with the one in the marker: if the object changed
  in S3 since this machine last pushed or pulled it, the file is a
  *conflict* — another machine wrote there — and is skipped; the run ends
  with exit 1 naming the conflicts. `--force` overwrites anyway. A file with
  no marker entry (never synced from here) is uploaded without a check.
- The marker is per directory, so `records/`, `courts/`, `liens/`, `data/`
  and the repo root (for `coverage.json`) each carry their own
  `.s3_sync.json`. They are git-ignored and machine-specific; deleting one
  just means the next push cannot detect a remote change.

## Configuration & secrets

Credential order in `get_client()`:

1. The standard boto3 chain (`~/.aws/credentials`, `AWS_*` env vars, an
   instance role).
2. Only if that chain is empty: `env_credentials()` reads the repo's
   git-ignored `.env` for `ACCESSKEYID=` / `SECRETACCESSKEY=` and optional
   `REGION=`. Values are never logged. On this host the keys live there, not
   in `~/.aws`.

Region: `s3.region` in `config.yml`, else `AWS_REGION`, else (for a directory
bucket) derived from the bucket name.

`.env` also holds the server's mail secrets; `compose.yml` deliberately does
**not** pass the whole file into the container, so the S3 keys never reach
it (see DEPLOY.md).

## Limits & gotchas

- **Refused outright:** any file name ending in `.db` or containing
  `cookie` (case-insensitive) exits 2 before any network call —
  `reviews.db`, `tx_cookie.txt`, `*_cookie.txt` stay on this machine.
  `.env` is simply never listed. Nothing in the repo copies `db/` anywhere.
- **Not a backup:** single-AZ, unversioned. Anything worth keeping long-term
  needs a second copy elsewhere; the collectors' `.cache/` directories are
  not mirrored at all.
- **Conflicts are per file, not per run:** a push can succeed for most files
  and still exit 1; re-run with `--force` only for the files you mean to
  overwrite.
- The `-v` flag turns on `DEBUG` logging including boto3's; nothing prints
  key material.
- `scripts/s3_push_all.sh` pushes `courts/trial_*.jsonl` by globbing, so a
  new court-portal adapter's output is picked up automatically; new files in
  `records/` or `liens/` must be added to the script by hand.
